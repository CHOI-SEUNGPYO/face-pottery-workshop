# 작은 흙 공방 프로토타입

캐릭터들과 토기를 빚고, 얼굴을 새기고, 발굴한 뒤 사진으로 남기는 웹게임이다. 현재 플레이에 사용하는 소스와 에셋, 바로 실행할 수 있는 `dist`를 보관한다.

## 게임 열기

PC 로컬 실행과 GitHub Pages 배포를 지원한다. 모든 실행·검사 명령은 `D:\togi\game` 안에서 실행한다. 마지막으로 확인한 배포 결과는 [진행 기록](PROGRESS.md)을 따른다.

웹 배포 주소: **[작은 흙 공방](https://choi-seungpyo.github.io/face-pottery-workshop/)**. `main`에 push하면 GitHub Actions가 빌드와 자동 검사를 거친 실행본을 GitHub Pages에 배포한다.

웹사이트와 PC 로컬 주소는 작품 저장 공간이 서로 다르다. PC에서 만든 작품은 기존 로컬 주소에서 계속 볼 수 있다. 유물 편집기는 PC에서 실행하며, 편집한 원본(`content/museum.json`, `asset/runtime/museum/`)을 commit·push하면 다음 웹 배포에 반영된다.

Node.js 22.12 이상이 설치된 Windows에서 **`게임실행.cmd`를 더블클릭**한다. 브라우저에서 [게임](http://127.0.0.1:4174/)이 열린다. 실행만 할 때는 패키지 설치나 빌드가 필요 없다.

터미널에서 실행하려면:

```powershell
cd D:\togi\game
npm start
```

실행 중에는 같은 주소로 다시 들어가면 된다. 그림·글꼴·소리·모델은 모두 로컬 파일이며, 유물 출처 링크를 열 때만 인터넷이 필요하다. 실행 기록은 Windows 임시 폴더의 `togi-prototype`에 남는다.

## 플레이

1. 얇게 표시된 토기 윤곽선을 잡고 좌우로 움직여 빚는다. 윤곽선 바깥쪽 6px 이내도 잡히며, 높이·넓이는 손잡이로 조절한다.
2. 위치가 고정된 **입구 넓이 / 테두리 높이 조절 막대**로 다듬는다. 휴대폰 세로에서는 아래에, PC와 가로 화면에서는 오른쪽에 놓인다. 넓이를 늘려도 높이나 조절 막대 위치가 내려가지 않는다. 조절 막대나 손잡이에 포커스를 둔 상태에서 방향키로도 조절한다. 드래그 한 번은 되돌리기 한 번으로 복구하며, Esc를 누르면 진행 중인 조절을 취소한다.
3. 얼굴의 **끌어 뚫기 / 그려 뚫기 / 선**을 고른다. 휴대폰의 기본 도구는 끌어 뚫기이며, 대각선으로 끌어 둥근 구멍의 너비와 높이를 정한다. 직접 그릴 때는 시작점 표시와 손가락용 닫힘 보정이 적용된다. **구멍 다듬기**로 테두리나 안쪽을 문지르면 지나간 구멍들이 한 번씩 부드러워진다. 한 번 문지르기는 되돌리기 한 번으로 복원한다. 구멍과 옆 구멍은 **톡 누르면 작은 기본 구멍**, **직접 그려 닫으면 그 모양의 구멍**으로 바로 뚫린다. 직접 그린 선을 원으로 바꾸지 않으며, 작은 손떨림과 시작점 근처의 작은 틈만 보정한다. 경계에서의 자동 위치 보정도 최대 4px로 제한한다. 넓게 굽은 표면에도 그릴 수 있고, 구멍이 합쳐지며 몸체와 연결이 끊긴 흙 조각은 함께 제거한다. 표면을 벗어나거나 닫히지 않은 선은 안내만 남기고 지운다. 윤곽을 따로 옮기는 조작은 없다. 구멍이 만들어지면 테두리에 짧은 빛이 지나가고 다듬기 도구가 강조된다.
4. 얼굴 만들기에 처음 들어가면 세 면을 순서대로 보여 주는 회전 시범과 두 손가락 동작이 나온다. 손을 대면 바로 멈추고 직접 조작할 수 있다. 움직임 줄이기에서는 시범을 생략한다. 이후 굽기, 상상 발굴, 시루에 얹기와 유물 비교를 거친다.
5. 마지막 전시의 오른쪽에는 **AI가 게임 도구로 만든 재현 예시**가 있다. 같은 몸체·구멍·다듬기 기능으로 세 얼굴과 옆 구멍을 만들었다. 마지막 전시는 이 예시 하나만 표시하며, 실제 사진은 사진첩에서 볼 수 있다. 이전 3D 에셋 파일은 보존하지만 플레이 중 불러오지 않는다. 사용자 작품이나 저장 데이터는 바뀌지 않는다. 화면과 전시 라벨, 사진에 AI 제작 표시를 남긴다. 완성한 작품과 캐릭터들을 1920×1080 PNG로 저장한다.

시작 화면에는 박물관에서 제공한 사업단·박물관 로고를 표시한다. **게임 소개·제작**에서 참여 기관과 `2026년 YU Digital HUSS AI를 활용한 디지털 뮤지엄 큐레이팅 과정` 지원 내용을 읽을 수 있다. 영상용 ‘100% AI·Higgsfield’ 문구는 게임의 실제 제작 방식에 맞게 바꿨다.

**실제 유물 사진**에서 얼굴모양토기 4장·시루 1장·배경 토기 8장을 볼 수 있다. 사진은 원래 비율과 색을 유지하고, 각 사진에 설명과 제공자·출처를 표시한다. 좌우 버튼이나 키보드 방향키로 넘기며 원본 크기로도 열 수 있다. 한 번에 선택한 사진을 불러오므로 처음 게임을 켤 때 배경 사진 전체를 내려받지 않는다. 사진 꾸미기를 마치면 실제 유물과 기관 크레딧이 있는 마무리 화면이 나오며, 닫으면 회전 가능한 내 작품으로 돌아간다.

시작 화면과 플레이 화면에 AI 제작 요소가 포함됐음을 표시한다. **제작·출처 안내**에서 AI로 생성·편집한 배경·캐릭터와 직접 빚는 내 토기, 실제 유물 사진의 차이를 확인할 수 있다. 저장 PNG에도 같은 표시가 함께 남는다. 표시 범위와 공식 안내를 검토한 근거는 [AI 제작 표시 안내](AI_DISCLOSURE.md)에 기록했다.

[경산시립박물관 공식 홈페이지](https://www.gbgs.go.kr/museum/main.do)는 시작 화면·도움말·유물 이야기에서 열 수 있다. 새 탭으로 열리므로 게임 화면을 그대로 두고 관람 정보를 확인할 수 있다.

보기 버튼 없이 화면에서 직접 둘러본다. 토기 밖을 좌우·위아래로 끌면 시점이 바뀐다. 휴대폰·태블릿에서는 토기 위라도 두 손가락으로 끌어 회전하고, 벌리거나 모아 확대·축소한다. 두 손가락 조작은 조형·구멍·흙 파기에 적용되지 않는다. PC에서는 마우스 오른쪽 끌기와 휠도 지원한다. 되돌리기·다시 실행과 키보드 조작, 움직임 줄이기, 음소거를 지원한다.

좌우 드래그는 화면에 보이는 토기 면이 손을 따라가는 방향이다. 장이나 선반이 시야를 가리면 해당 가구와 장식이 잠시 숨겨지며 바닥과 작업대는 유지한다. 마지막 비교·완성 화면에서는 **내 토기와 참고 토기를 각각 잡고 돌릴 수 있다**. 내 토기의 회전 방향은 저장하며, 빈 곳과 두 손가락 조작은 시점을 바꾼다. 전시실은 두 작품이 나란히 보이는 시점 범위를 유지한다.

## 저장

현재 작품과 진행 상태는 브라우저의 `togi-workshop-v2`에 자동 저장한다. 직전 정상 저장본도 복구용으로 보관한다. 이전 작품을 열 때 저장된 원본을 덮어쓰지 않는다. 예전 구멍 안에 떠 있던 흙 조각과 관통 방향은 화면에 표시할 때 보정한다.

저장한 작품을 이어서 보려면 **같은 브라우저와 같은 주소 `http://127.0.0.1:4174/`**를 사용한다. 개발 주소의 4173번 포트는 별도 저장 공간이다. 브라우저의 사이트 데이터를 지우면 저장 작품도 지워질 수 있다.

예전 `face-pottery-v1` 저장 데이터는 건드리지 않는다. 이전 버전 감상 화면과 편집 원본·시안은 프로젝트 정리 시 복구용 ZIP으로 옮겼다: `D:\togi-prototype-backup-20261109-utf8.zip`.

## 화면과 유물 이야기

도구 받침은 작업대와 다른 테두리·천 안감으로 구분한다. 눈·입 메뉴와 캐릭터 말풍선은 간격을 두고 함께 배치하며, 작은 세로 화면에서 메뉴를 펼치면 사용 설명도 메뉴 안에서 읽는다. 발굴에서는 지면 아래로 시점이 내려가지 않으며 확대해도 발굴 구역이 작업 화면 안에 남는다. 마지막 전시실은 제공된 경산시립박물관 사진과 공식 VR의 색·진열장을 참고한 게임 공간이다.

발굴·얹기 장면의 시루는 공식 발굴 사진을 참고한 3D 모델이다. 바닥이 제거된 긴 몸통, 깨진 가장자리와 몸통 중간의 소뿔 모양 손잡이 두 개를 반영했다. 얼굴토기와 결합해 사용했을 가능성을 살펴보는 장면이며, 치수를 측정한 복원이나 실제 사용법의 확정은 아니다.

가로 화면에서는 왼쪽에 짧은 사용 설명, 오른쪽에 유물 이야기와 작업 설정, 아래에 펼침형 액션바가 놓인다. 작은 가로 화면에서는 토기 옆 높이·넓이 손잡이를 사용한다. 휴대폰은 세로·가로 모두 플레이할 수 있다. 세로에서는 유물 이야기를 상단 책 버튼으로 열고, 얼굴 만들기 도구 네 개는 하단 한 줄에서 바로 고른다. 설명·단계 상태·마무리 버튼은 짧게 배치하며, 현재 도구와 주소창이 남긴 공간에 맞춰 작품의 위치와 크기를 정한다. 사진 꾸미기의 크기·회전·삭제는 스티커를 선택했을 때 나타난다. 화면 방향을 바꾸어도 완성한 조형과 진행 상태를 유지하며 굽기·이동도 계속된다. 태블릿 배치는 유지한다. 유물 이야기 버튼을 누르면 사진과 단계별 이야기를 페이지로 넘겨 볼 수 있다.

**`유물편집.cmd`를 더블클릭**하면 별도 설치 없이 편집 화면이 열린다. 실행 주소는 `http://127.0.0.1:4175/`다.

1. 게임 단계를 고르고 제목·요약·이야기 문단을 수정한다. 요약은 카드에 들어가도록 140자까지 작성한다.
2. 사진을 추가하거나 선택한 사진을 교체하고, 설명·대체 설명·제공자·이용 조건·출처를 기록한다.
   사진첩 분류와 짧은 이름도 정할 수 있다. 분류가 없는 예전 자료는 ‘더 많은 자료’에 표시한다.
3. 단계별 대표 사진과 문단의 **확인된 내용 / 연구자의 해석 / 게임 속 상상** 구분을 정한다.
4. **저장하고 게임에 반영**을 누르고 게임을 새로고침한다. 글·사진 변경은 재빌드가 필요 없다.

원본은 `content/museum.json`, 사진·모델은 `asset/runtime/museum/`에 저장한다. 실행본의 `dist/museum/`에도 동시에 반영한다. 다른 PC로 옮길 때 프로젝트 전체 또는 실행용 `dist` 전체를 복사한다. 직전 저장본은 **직전 저장본 복구**로 되돌릴 수 있다. 사용자의 토기 저장과는 별도다. 추가한 파일은 복구를 위해 원본 폴더에 보관한다.

배경 유물은 **배경 전시 유물 → 모델 추가**에서 GLB를 등록하고 전시 높이·위치·회전·연결할 이야기를 지정한다. 모델의 가장 낮은 지점을 바닥으로 맞추고, 지정한 전시 높이에 맞춰 크기를 조절한다. 뒤쪽 선반에 올리려면 위치의 Y를 선반 높이로 맞춘다. 등록된 모델은 방과 분리되어 로드되며, 누르면 연결된 이야기가 열린다. 모델이 없으면 기존 장식 토기를 표시한다. 마지막 비교 전시에는 AI가 게임 도구로 만든 예시만 표시한다. 추가 자료의 출처와 이용 조건은 운영자가 기록한다.

굽기는 **넣기 → 굽기 → 식히기 → 꺼내기**로 이어지는 약 14초의 체험 연출이다. 토기는 앞쪽 받침에서 가마 바닥으로 연속해서 움직이고, 식힌 뒤 받침으로 돌아온다. 연출 중에는 벽이 서서히 열려 내부와 단계별 행동을 함께 보여준다. 이때 수동 내부 보기 버튼은 숨긴다. 불빛·불티·열기 소리·재질 변화가 함께 동작한다. 유물 이야기를 열면 연출도 멈추고, **연출 건너뛰기**로 즉시 완성할 수 있다. 움직임 줄이기 설정에서는 카메라 움직임과 불티를 줄이고 약 4초로 보여준다. 실제 유물의 가마나 소성 과정을 복원한 장면은 아니다.

**가마와 이 장면 알아보기**에서는 가마의 뜻과 아궁이·소성실·연도의 역할을 살펴본다. 흙으로 덮인 형태를 참고한 이유, 옆면을 펼쳐 내부를 보여 주는 연출, 짧게 줄인 굽기 과정과 실제로 확인되지 않은 부분을 구분해 설명한다. 굽는 동안 시점을 자동으로 움직이지 않으며, 담장 윗면의 중첩도 제거했다.

처음에는 공방에 필요한 모델과 재질만 준비한다. 가마·발굴장은 내 토기를 살펴볼 때, 박물관은 시루에 얹을 때 미리 준비한다. 준비가 덜 된 장면에 들어가면 이동 화면에서 기다리고, 연결에 실패하면 현재 작품과 단계는 유지한 채 다시 시도할 수 있다. 마지막 단계에 저장한 작품도 공방 첫 화면을 먼저 보여 주고 **이어 만들기**를 누르면 해당 장소를 준비한다.

## 코드 수정과 재빌드

```powershell
npm ci
npm run dev
```

```powershell
npm run verify
```

빌드는 타입 검사와 이용 문서 복사까지 수행한다. `check:openings`는 구멍의 관통 방향, 넓은 곡면의 그리기, 떨어진 흙 조각 제거와 저장 작품 보존을 검사한다. `npm test`는 임시 포트에서 실제 실행본을 열어 파일 응답과 기본 접근 제한을 확인하며, 추가 패키지 없이도 실행할 수 있다. 서버를 실행 중이었다면 빌드 후 브라우저를 새로고침한다.

`verify`는 빌드와 위 검사, 데스크톱·모바일 조작 검사(`check:ui`)를 한 번에 실행한다. 조작 검사는 PC에 설치된 Microsoft Edge를 사용하며, 검사 전용 주소와 새 브라우저 환경에서 실행하므로 사용자의 작품에 접근하지 않는다. 실패 화면과 새 조작의 핵심 확인 화면은 `asset/review/`에 남기며 실행본에는 포함하지 않는다. 평소에는 수정을 모은 뒤 한 번 실행하고, 실패한 검사만 다시 실행한다. 그림·배치가 달라졌을 때만 핵심 화면을 별도로 살펴본다. Playwright는 개발 검사에만 쓰며 실행본에는 포함되지 않는다.

`check:workshop`는 1280×720·1366×768·1920×1080의 배치, 굽기 단계·일시 정지·건너뛰기, 이야기 페이지, 글·사진·GLB 편집과 복구를 검사한다. 편집 검사는 임시 폴더의 가상 자료만 사용한다. 게임과 편집기는 각각 검사 전용 임시 포트에서 실행하며 실제 작품이나 유물 자료를 덮어쓰지 않는다.

`check:journey`는 개발 서버의 별도 검사 환경에서 몸체 밖 회전, 몸체 손잡이·고정된 입구 조절 막대, 도구 간 겹침, 마우스·휴대폰 터치 발굴, 시루 얹기 단계의 저장 후 이어하기, 세로·가로 화면의 사진 도구와 1920×1080 PNG, 두 손가락 시점 조작 중 작품·흙 보존을 검사한다. `check:workshop`도 320×568·390×844 세로, 740×360 가로와 태블릿 크기의 발굴·시루 얹기·비교 화면을 검사한다. 실제 휴대기기의 속도·발열 검사는 별도다.

`check:mobile`은 새 작품에서 시작해 화면의 버튼과 끌기로 끝까지 진행한다. 몸체·입구 조절, 얼굴 그리기, 수정 후 복귀, 전체 굽기, 손으로 흙 파기, 시루에 끌어 얹기, 두 유물 회전, 사진 저장과 사진첩을 거쳐 완성 화면에 도착한다. 390×696에서 시작하고 320×568·740×360으로도 바꿔 본다. 실제 토기의 화면상 윤곽과 메뉴의 겹침, 44px 터치 영역, 얹는 도중의 가림을 검사한다. 끌기와 그리기는 브라우저의 네이티브 터치 이벤트를 사용한다. Edge 자동 입력에서 끌기 뒤 첫 탭의 클릭이 빠지는 현상은 단순 HTML에서도 재현되어, 버튼 활성화는 Playwright 클릭을 사용한다. 단계나 저장 상태를 검사 코드로 건너뛰지 않으며, 브라우저 저장은 사용자의 작품과 분리한다.

`check:performance`는 유물이 묻힌 상태와 드러난 상태에서 흙 파기 처리 시간을 측정하고, 세로 화면·CPU 4배 감속 조건에서도 긴 입력 지연이 생기는지 확인한다. 이는 브러시 계산 시간이며 전체 프레임 속도나 실제 휴대폰 성능 수치는 아니다. 시루 표면 탐색을 미리 계산한 공간 색인으로 가속하고, 중복 표면 탐색·브러시 보간을 줄이며, 흙을 파는 중 그림자 갱신 빈도를 제한한다. 지면은 매 프레임 갱신하고 손을 떼면 그림자도 최종 갱신한다.

GitHub에서는 동일 커밋의 실행본을 만든 뒤 조작·작업실·모바일 여정·3D 에셋·성능 검사를 각각 독립된 환경에서 수행한다. 모든 항목을 통과해야 그 실행본을 배포한다. 느린 프레임에서도 굽기의 넣기·가열·냉각·꺼내기 단계가 생략되지 않도록 진행 폭을 제한하며, `npm test`에서 정상 속도와 지연 상황을 함께 검사한다.

## 남겨 둔 파일

- `src/`: 화면, 조형·그리기·발굴, 저장, 소리와 3D 렌더링 코드.
- `asset/runtime/`: 사용하는 캐릭터 PNG·WebP, 재질 JPG·WebP, 장면 GLB, 버튼 SVG, WAV.
- `asset/source/`: 새 아트의 PNG 원본, 모델 목록, 제작 지시와 출처 설명.
- `../reference/video/`, `../04_목록/`: 사용자 제공 영상과 제작자가 전달한 참고 원본. 게임 폴더 밖에 보관하며 실행본·Git에는 넣지 않는다.
- `content/`, `asset/runtime/museum/`: 편집 가능한 유물 이야기와 사진·모델 원본.
- `유물편집.cmd`, `Start-Editor.ps1`, `scripts/museum-editor.*`: 유물 편집 도구. Node.js만으로 실행한다.
- `font/`, `assets/`: 사용하는 글꼴과 이용 문서, 실제 유물 사진과 출처.
- `dist/`: 바로 실행하는 게임과 이용 문서. 재빌드하면 갱신된다.
- `server.mjs`, `Start-Game.ps1`, `게임실행.cmd`: 로컬 실행 도구.
- `scripts/`: 빌드 시 이용 문서 복사와 최소 실행 검사.

TypeScript·Vite·Three.js를 사용한다. 토기 조형은 회전형 곡선 편집이며 점토 물리 해석은 아니다. 유물에서 확인한 특징, 사용법의 추정, 체험용 상상은 화면에서 구분한다. 자료와 이용 조건은 [출처 문서](assets/CREDITS.md)에 보관한다.

## 2026-11 화면 개편

- 휴대폰·태블릿은 세로·가로 모두 지원한다. 방향 전환 시 진행 중인 손동작만 취소하고 확정한 작품과 진행 상태는 유지한다.
- 토기 밖 드래그 또는 두 손가락으로 시점을 움직인다. 보기 액션바는 없애고 그리기·수정만 펼침형 액션바로 선택한다. 입구는 토기 옆 손잡이로 조절한다.
- 눈·입은 얇게, 옆 구멍은 길게 돌출된다. 서로 다른 도구의 구멍과 돌출 테두리가 실제로 겹칠 때만 새 표현을 막는다. 기존 저장 작품의 겹침을 삭제하지 않는다.
- 발굴 완료 시 같은 현장에서 시루 얹기 이벤트가 열린다. 얹기를 마친 뒤 박물관으로 이동한다.
- 가마는 당시 영남 지역 반지하식 등요 자료를 참고한 체험용 구성이다. 소월리 유물의 제작 가마가 확인된 복원으로 설명하지 않는다. `내부 보기`는 설명용 단면이다.
- 박물관 오른쪽은 AI가 게임 도구로 만든 얼굴모양토기 재현 예시다. 내 작품과 예시를 각각 회전할 수 있다. 이전 사진 참고 3D 모델(`face-artifact-v3.glb`, `face-artifact-v4.glb`)은 파일로 보존하되 플레이 중 불러오지 않는다. 실제 사진과 출처는 유물 이야기에서 확인한다. 촬영 후 세 캐릭터 스티커로 꾸미고 PNG로 저장할 수 있다.
- 이동 연출은 경산이·독이·압이 세 명이 제공 사진의 얼굴토기 전체를 옆으로 눕혀 함께 받쳐 들고 간다. 토기는 별도 공통 에셋이며 사용자 작품이 아니다.
- 기존 실행 에셋은 보존했다. 새 애니메이션은 `asset/runtime/animations/`, 추가 참고 사진은 `asset/runtime/museum/face-reference.jpg`에 둔다.

## 영상 참고 아트 적용 · 2026-11-15

공방·박물관·발굴장·가마는 사전 제작한 GLB와 이미지 재질을 사용한다. 선반 토기 8종, 제작·발굴 도구 10종, 이를 배치한 공간 및 주변 요소 10개를 만들었다. 나무·흙·회벽·천·토기 표면·정원·식생 등 이미지 8개와 입체감을 더한 캐릭터 3개를 연결했다. 원래 에셋은 보존한다.

공방의 큰 빈 공간은 선반과 도구로 채우고 작업 영역에 조금 더 가까이 배치했다. 토기를 뒤에서 볼 때는 시야를 가리는 실내 벽과 선반이 열리며 바닥은 유지한다. 기존 조형·구멍·발굴·시루 얹기·사진 저장과 세로·가로 조작 방식은 유지한다.

모델을 수정한 뒤 `npm run build:art`, 일반 게임 수정 뒤에는 `npm run verify`를 실행한다. `check:art`는 새 브라우저에서 장면별 에셋 로딩, 재질 표시, 면 수·그리기 횟수, 가마 단면과 뒤쪽 시야, 작품 원본 보존을 검사한다. `TOGI_REVIEW=1`일 때만 변경한 대표 화면을 `asset/review/`에 저장한다. 이 검사는 실제 휴대폰의 속도·발열 검증을 대신하지 않는다.

제작 지시와 원본 경로는 [아트 원본 안내](asset/source/README.md)에 있다. 이번 변경은 재질·공간·정지 캐릭터 이미지의 개선이며 영상과 같은 전체 캐릭터 동작·연출을 완성했다는 뜻은 아니다.

`check:ui`의 `check-guidance.mjs`는 빠른 로딩 표시 시간, 세 면 회전과 터치 중단, 넓혀도 움직이지 않는 입구 조절 막대, 손가락 구멍 그리기·문질러 다듬기·되돌리기, AI 예시 회전 시 사용자 작품 보존을 검사한다.

같은 묶음의 `check-loading.mjs`는 공방만 불러오는 첫 로딩, 다음 장소의 다운로드 실패·재시도, 성공한 파일 재사용, 단일 AI 전시, 마지막 단계 작품의 이어하기를 검사한다.
